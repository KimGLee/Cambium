## Control Registry

The [[kernel/K00 Standards Control/11 Standards Map and Rule Registry#Cross-domain Rule Registry|Cross-domain Rule Registry]] governs content rules — "where the rule lives"; this Control Registry governs control obligations — "where the check happens". Each risk object has one and only one canonical gate. Other layers either consume a still-valid receipt or invoke that same gate against a newly required snapshot; they never reimplement it as a parallel check.

| Risk object | Canonical gate (sole) | Behavior of other layers |
|---|---|---|
| Runtime Card completeness and source synchronization | Governance close: [[kernel/K00 Standards Control/03 Standards Governance#Revision Write-back Checklist|Revision Write-back Checklist]] runs `Tools/stamp_cards.py . --check` | Routine tasks consume the kernel Cards; profile loading cannot waive the gate, and knowledge-page scans exclude compiled Cards rather than re-validating them |
| Existing runtime discovery, new-task collision, and interrupted-writer recovery | [[kernel/K00 Standards Control/13 Runtime Admission and Recovery#Runtime Startup Gate|Runtime Startup Gate]] probes `.cambium/` and requires `check_queue.py --resume-status` before any state write when it exists | R01, R07, and task-specific routes consume this boundary; none may initialize over, reset, or infer around existing state |
| Large-scale execution admission | [[kernel/K00 Standards Control/13 Runtime Admission and Recovery#Large-scale Pre-execution Gate|Large-scale Pre-execution Gate]] | R11 packages the gate with the actual work route; it neither copies the checklist nor authorizes content work by itself |
| Wiki link integrity | Batch close: [[kernel/K12 Quality Assurance/09 Batch-close Closed List#Batch-close Closed List|Closed List]] check_links produces the receipt | Note close: only this page's `--scope` self-check; migration/retirement: targeted retargeting only; the Terminal Audit invokes the same Closed List gate again against the final frozen snapshot |
| Frontmatter vocabulary | Batch close: [[kernel/K12 Quality Assurance/09 Batch-close Closed List#Batch-close Closed List|Closed List]] item 7 check_vocab produces the receipt | Note close: `--scope` self-check; the Terminal Audit invokes the same Closed List gate again against the final frozen snapshot |
| Queue structure, dependencies, readiness, and Queue/Coverage/Progress drift | [[kernel/K13 Task Runtime and Execution Control/08 Required Queue Contract and Lifecycle|K13/08]]: `Tools/check_queue.py` produces the current Queue receipt | Admission, activation, resume, batch close, and Terminal Audit consume that receipt or request the corresponding mode; they do not reimplement Queue validation |
| Concurrent write conflicts | At batch activation: `Tools/check_queue.py --require-ready <batch-id>` validates Coverage manifest intersection, execution mode, and the concurrency cap ([[kernel/K13 Task Runtime and Execution Control/10 Batch Admission Transitions and Serial Integration|K13/10]]) | Concurrent batches write only their own manifest pages, receipts directory, and delta files; global state files are integrator-exclusive |
| Content correctness (manual) | Note close: [[kernel/K12 Quality Assurance/01 Quality Dimensions and Single Note Review|K12/01]] review by tier | Batch-level manual review scope = changed ∪ invalidated ∪ sampled; long-term P0 assurance is carried by freshness re-review; the Terminal Audit verifies receipts + bounded sampling |
| Coverage reconciliation | Batch close: file-count only (Closed List item 4); the issue list runs per [[kernel/K12 Quality Assurance/03 Module and Coverage Review|K12/03]] before module completion and completion-candidate | Once after inventory and once on scope/guidance changes; no reconciliation at batch start; before completion-candidate it merges with Terminal Audit step 4 |
| Standards version consistency | Automatic version self-check at batch activation: [[kernel/K12 Quality Assurance/10 Standards Version Adoption#Active-task Adoption|Active-task Adoption]] | With a delta, incremental adoption; with no delta, a one-line receipt; the Terminal Audit validates via check_proof |
| Guidance disposition | One full disposition at intake: [[kernel/K13 Task Runtime and Execution Control/05 Guidance Disposition and Safe Switching|K13/05]] after K13/04 classification (threshold: significant Guidance) | Batch close reconciles only the increment after `last_reconciled_guidance_id`; the Terminal Audit verifies dispositions read-only from the ledger |
| Receipt validity | AuditPlan once before batch close: [[kernel/K12 Quality Assurance/07 Audit Evidence Reuse and Invalidation|K12/07]] | At batch start only the Receipt Register is loaded; the Reuse Gate conditions remain |
| Rendering | Note close Level 0/1: [[kernel/K12 Quality Assurance/02 Rendering Verification|K12/02]] | Batch close: one enumerated check item; the Terminal Audit trusts the receipt |
| Registered residual-content scan | Batch close: [[kernel/K12 Quality Assurance/09 Batch-close Closed List#Batch-close Closed List|Closed List]] item 6 + the `Registered Scan Registry` residual-scan hook | Other layers reference the Closed List and the registered hooks; no separate corpus-wide scan |
| Duplicate detection | Maintenance runs and governance tasks: [[kernel/K12 Quality Assurance/05 Automated and Manual Checks|K12/05]] duplicate_check | At batch level only the Closed List's basename-level check; paragraph-level scans do not run every batch |
| Knowledge freshness | check_freshness at maintenance-run start: [[kernel/K08 Metadata and Status/05 Review Source and Migration Metadata|K08/05]] | Not in the batch automatic check list |
| Depth balance | Module close: [[kernel/K12 Quality Assurance/03 Module and Coverage Review#Module Review|K12/03]] Module Review | Coverage Reconciliation's core-versus-frontier line raises review candidates only and emits no receipt |
| Prerequisite completeness | Module close: [[kernel/K12 Quality Assurance/03 Module and Coverage Review#Module Review|K12/03]] Module Review | check_links owns link resolution; unexplained P0 / P1 concepts and chain continuity are judged from content and are not re-derived from link results |
| Canonical ownership uniqueness | Module close: [[kernel/K12 Quality Assurance/03 Module and Coverage Review#Module Review|K12/03]] Module Review duplicate item | Closed List item 3 produces basename candidates only; duplicate headings inside one page are a [[kernel/K12 Quality Assurance/02 Rendering Verification|K12/02]] Level 0 finding |
